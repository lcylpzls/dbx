# dbx 产品需求(PRD)

> 版本:v0.0.0(规划稿) · 状态:评审中

## 1. 背景与动机

AI 辅助开发普及后,生成性能良好、参数化的原生 SQL 已经很容易。由此带来的新问题不再是「写不出 SQL」,而是「一致性」:

- 每个项目的连接管理、事务边界、结构体扫描、动态条件拼装、慢查询日志各写各的;
- AI 在动态过滤/排序/分页场景下倾向于生成 `WHERE 1=1` 与字符串拼接,埋下注入风险与维护负担;
- 完整 ORM(GORM / ent)引入大量抽象,AI 生成的 ORM 代码容易出现 API 幻觉与 N+1 查询,且难以调试。

结论:**不做完整 ORM,做一个差异化的薄数据访问层**,把「安全、可读、统一」沉淀为库能力,SQL 主体继续由开发者/AI 编写。

## 2. 目标

1. 统一三种数据库(MySQL / SQLite / PostgreSQL)的连接、事务、扫描与错误处理;
2. 动态查询安全构造,杜绝字符串拼接导致的注入;
3. 与 logx / errx 打通,慢查询、错误、耗时默认可观测;
4. 保持原生 SQL 的可审查性与性能透明,不引入运行时代价;
5. 提供轻量迁移,让 schema 变更与代码一起版本化。

## 3. 非目标(明确不做)

- 不做表结构到结构体的自动映射与自动建表;
- 不做关联加载 / 预加载 / 懒加载(N+1 风险源);
- 不做 SQL 方言翻译(一条 SQL 自动适配三种数据库);
- 不做缓存层、分库分表、读写分离;
- 不追求与 GORM / ent 的 API 兼容。

## 4. 支持范围

| 数据库 | 驱动 | 子包 | 备注 |
| --- | --- | --- | --- |
| MySQL 5.7+ / 8.x | go-sql-driver/mysql | `dbx/mysql` | 推荐 utf8mb4 |
| SQLite 3.x | modernc.org/sqlite | `dbx/sqlite` | 纯 Go,无 CGO,支持内存库 |
| PostgreSQL 12+ | jackc/pgx(stdlib 模式) | `dbx/pg` | 占位符 `$1..$n`,支持 Returning |

Go 版本:**1.26+**(与 webx 及当前开发环境一致)。

## 5. 能力需求

### 5.1 连接管理

- `Open` / `OpenConfig` 创建连接,支持连接池参数(最大打开/空闲连接、连接生命周期、空闲超时);
- `Ping` 探测、`Close` 优雅关闭;打开失败返回结构化错误。

### 5.2 查询执行

- `Exec` / `Query` / `QueryRow` 三件套,签名与 `database/sql` 对齐,但错误统一包装为 errx;
- 所有参数必须走占位符;**禁止提供「格式化拼接 SQL」的公共 API**。

### 5.3 结构体扫描

- `One[T]` / `List[T]` 泛型扫描到结构体;
- `db:"column"` tag 指定列名,`db:"-"` 忽略字段,支持嵌入结构体;
- NULL 处理:NULL 值按目标类型归零;指针字段与 `sql.Scanner` 类型原生支持;
- 字段元信息缓存(`sync.Map`),扫描热路径不重复反射;
- 提供 `RowMapper` 自定义映射兜底。

### 5.4 动态构造

- 条件构造器:相等/不等、IN、LIKE、范围、IS NULL、AND/OR 组合与嵌套;
- 排序:列名走白名单校验(默认仅字母、数字、下划线、点),方向固定 ASC/DESC;
- 分页:`Page(页号, 每页)` 或 `LimitOffset`;三种方言分别生成 `LIMIT ? OFFSET ?`(MySQL/SQLite)与 `LIMIT $n OFFSET $n+1`(PostgreSQL);
- 构造器输出 `(sql string, args []any)`,参数顺序与占位符严格对应。

### 5.5 事务

- `WithTx(ctx, fn)` 自动提交/回滚;回调返回错误或 panic 时回滚;
- 支持隔离级别与只读选项;
- 嵌套事务使用保存点(三种数据库均支持);
- `Tx` 暴露与 `DB` 相同的执行与扫描方法。

### 5.6 可观测性

- 慢查询日志(阈值可配置,默认 100ms),记录 SQL、参数、耗时;
- 指标钩子:查询次数、失败次数、慢查询次数、耗时分布;
- 日志统一走 logx,不直接向控制台打印。

### 5.7 错误模型

- 对外错误全部为 errx 结构化错误,错误码 `DBX_*`;
- `sql.ErrNoRows` 统一包装为 `DBX_NOT_FOUND`,并提供 `IsNotFound` 判定助手;
- 驱动错误保留原始错误链(`Unwrap`),不吞错。

### 5.8 迁移

- `dbx/migrate` 子包:按文件名顺序执行 `*.sql`,记录到 `schema_migrations` 版本表;
- 支持 `embed.FS` 与本地目录;版本表结构三方言兼容;
- v0.1 先支持 up-only,down 回滚留待 v0.2。

## 6. 非功能需求

- **性能**:动态构造与扫描热路径低分配,基准目标见迭代计划;
- **安全**:动态 SQL 只经构造器生成;标识符白名单校验;禁止公共字符串拼接 API;
- **兼容**:核心包不依赖第三方驱动,驱动选择由子包隔离;
- **质量**:语句覆盖率 100%、race、staticcheck、vet、fuzz、三平台 CI(门槛见迭代计划)。

## 7. 验收标准

v1.0.0 发布时:

1. 三种数据库的全部能力有集成测试覆盖(CI 使用 MySQL/PostgreSQL 服务容器,SQLite 进程内);
2. 动态构造器 fuzz 测试证明:任意输入不会生成可注入的 SQL;
3. 100% 语句覆盖率,`go test -race ./...`、staticcheck、go vet 全绿;
4. 文档中的每个 API 示例均可运行;
5. v0.1.0 建立 API 基线,后续破坏性变更触发 apidiff 检查。
